# Plan: Date Selection & Optional Food Items for POS Bookings

## Overview
Add two features to the cinema POS booking system:
1. **Date selection** - Allow choosing any date for bookings (currently only today's shows are shown)
2. **Optional food items** - Add concession items (popcorn, drinks, snacks) that can be optionally added to bookings

---

## Task 1: Date Selection on POS Page

### Changes Required:
- `app/dashboard/pos/page.tsx`
  - Add a date picker input above the show selector
  - Replace hardcoded "today" fetch with state-controlled date
  - Fetch shows from `/api/shows?date=YYYY-MM-DD` based on selected date
  - Default to today's date, allow navigation to past/future dates
  - Update show cards to display full date (day + date) for clarity

### UX Details:
- Use native HTML `<input type="date">` styled consistently
- Date defaults to today; cannot be before today for booking purposes
- Show formatted date (e.g., "Mon, 24 Apr") on show cards when date differs from today
- Fetch error handling with retry on date change

## Task 2: Food/Items Data Model

### Prisma Schema Updates (`prisma/schema.prisma`):
```prisma
model FoodItem {
  id          String   @id @default(cuid())
  name        String
  description String?
  price       Float
  category    String   // "POPCORN", "DRINKS", "SNACKS", "COMBO"
  imageUrl    String?
  available   Boolean  @default(true)
  sortOrder   Int      @default(0)
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  bookingItems BookingItem[]
}

model BookingItem {
  id        String  @id @default(cuid())
  bookingId String
  foodItemId String
  quantity  Int     @default(1)
  price     Float   // price at time of booking (snapshot)

  booking   Booking @relation(fields: [bookingId], references: [id], onDelete: Cascade)
  foodItem  FoodItem @relation(fields: [foodItemId], references: [id])

  @@unique([bookingId, foodItemId])
}

- Update `Booking` model: add `bookingItems BookingItem[]` relation
- Run: `npx prisma generate && npx prisma db push`

## Task 3: Food Item Management APIs

### New Endpoints: `app/api/food/route.ts` (GET list) and `app/api/food/[id]/route.ts` (CRUD)

**GET `/api/food`** - List all available food items (active only by default)
- Query params: `?category=`, `?available=`
- Response: `{ items: FoodItem[] }`

**POST `/api/food`** - Create new food item (admin only)
- Body: `{ name, description, price, category, imageUrl?, available?, sortOrder? }`
- Auth: Requires MANAGER+ role

**PATCH `/api/food/[id]`** - Update food item (admin only)
- Body: partial fields

**DELETE `/api/food/[id]`** - Soft-delete by setting `available: false` (admin only)

## Task 5: Update Booking Creation

### Changes in `app/api/bookings/route.ts` POST handler:
- Extend schema to accept `foodItems?: Array<{ foodItemId: string; quantity: number }>`
- Fetch food items and validate all exist & are available
- Calculate food total = sum(item.price × quantity)
- New total = seatTotal + foodTotal - discount
- Create `BookingItem` records alongside booking in the same transaction
- Include `foodItems` in the booking response with names/prices

### Validation:
- Reject if any foodItemId invalid or unavailable
- Max 99 quantity per item (reasonable limit)

## Implementation Order

3. **Phase 3 - Food APIs** (backend)

5. **Phase 5 - Booking Integration** (backend)
   - Extend booking POST schema to accept `foodItems?: Array<{ foodItemId: string; quantity: number }>`

   - Calculate totals: seatTotal + foodTotal - discount

6. **Phase 6 - Ticket Updates** (ticket generation)
   - Extend `TicketData` interface with `foodItems?: Array<{ name: string; quantity: number; price: number }>`

7. **Phase 7 - Validation & Polishing**
   - Run `npm run lint` and `npm run typecheck`
   - Add seed data to `prisma/seed.js` (including typical cinema items)
   - Add Playwright test for food selection flow
   - Update POS test to flow through new 3-step process
   - Manual smoke test with date selection + full booking + ticket generation
